# 家里的音乐：小爱音箱语音点歌与长期曲库

版本：0.2.0 · 编写与核实日期：2026-11-05

本包面向 **小米小爱音箱 Pro + 家庭 Linux 服务器**。提供 Songloft 部署配置、智能音箱插件自动配置、开放音源搜索和自动保存程序，并附两首有来源及许可记录的 MP3 试听曲。

**当前交付状态：本版修复了验收发现的下载与连接问题，并加入主曲库自动同步；本地回归通过，但完整家庭使用验收仍未完成。尚未连接你的家庭服务器或真实音箱。实际绑定需要在你家运行部署，并在本机完成小米扫码登录和设备选择。**

## 1. 实现的使用方式

安装并绑定后，可按下列顺序使用：

1. 对音箱说“小爱同学，播放歌曲致爱丽丝”。
2. Songloft 的智能音箱插件先查你家的曲库。
3. 本地没有时，调用本包的开放音乐搜索服务；只选择明确匹配且授权字段满足要求的录音。
4. 首次可从服务器中转播放，同时后台保存 MP3。
5. 保存完成且完整解码校验通过后，同一播放地址读取家里的文件；后台自动登记 Songloft 曲目及 MIoT 配置的外部歌曲导入歌单（新安装默认为“免费音乐”）。

还可通过手机浏览器打开曲库助手，搜索版本、保存、设置中文点歌名，例如把一段录音命名为“晚安音乐”。已有的普通 MP3 可直接放进 `music/`，在 Songloft 扫描后点播。

### “免费”具体指什么

- Songloft 与本包程序不需要音乐会员或付费大模型 API。
- 随包试听曲和默认自动搜索来源采用明确开放许可；保存后可以按各自许可长期使用，并保留作者和来源。
- 自己已合法取得的普通音频也可以导入。会员应用中的加密缓存不等于可导入的 MP3。
- 这不是完整商业流行音乐曲库，不能保证任何指定歌手的所有原唱都能免费找到。没有匹配录音时明确返回未找到。
- 在线音源、小米账号接口和家庭网络都可能变化；本地音频可长期保存，语音点歌仍依赖小米云端识别/对话接口。服务器电费、存储和网络成本仍由家庭承担。

## 2. 组成与数据保存

| 组成 | 用途 | 默认地址或目录 |
|---|---|---|
| Songloft 2.13.8 Full | 主音乐软件、曲库、歌单、网页播放 | `http://服务器局域网IP:58091` |
| MIoT 2026.11.1.3 智能音箱插件 | 账号绑定、语音监听、点歌与音箱播放 | Songloft 内的“智能音箱” |
| 本包免费曲库助手 | 搜索、下载、中文别名、查看保存状态 | `http://服务器局域网IP:58092` |
| 手动音乐目录 | 你已有的音频和随包试听曲 | `music/` |
| 自动保存的音乐 | 下载到本机的 MP3 | `provider-data/audio/开放音乐/` |
| 音源记录 | 每首歌的作者、许可、来源与处理说明 | `provider-data/credits/` |
| 曲库助手数据库 | 曲目状态、中文别名 | `provider-data/catalogue.sqlite3` |
| Songloft 数据 | 曲目、歌单、插件、小米登录状态等 | `songloft-data/` |

联网歌曲在 Songloft 中通过稳定的**家庭服务器音频地址**登记；音频由曲库助手保存到本机。不会同时把自动下载目录再交给 Songloft 扫描，避免同一首歌出现两个条目。

曲库助手分别显示**已保存**与**已同步到主曲库和歌单**。前者需要完整解码 MP3，并检查实际时长与源信息是否一致；后者需要主软件确认导入及歌单登记，并确认 MIoT 索引刷新时间推进；这仍不等于音箱已实际播放。主软件暂时不可连接时，MP3 保留并约每 30 秒重试登记；已保存的音乐仍可从助手播放。单独运行 provider 而未配置主软件连接时，会明确显示自动同步未配置。

## 3. 安装前准备

- 一台家庭 Linux 服务器，具备 Python 3.10+、Docker Engine 与 Docker Compose v2。
- 服务器和音箱在可互访的局域网；音箱不能被访客 Wi-Fi 或 AP 隔离挡住。
- 使用音箱所属的小米账号完成本机登录。
- 首次安装需要访问 Docker Hub、Debian 包源、GitHub；在线搜歌还需访问 `commons.wikimedia.org` 和 `upload.wikimedia.org`。
- 在路由器给服务器做 DHCP 地址保留，保证家庭 IP 稳定。

本包按照明确的局域网 IP 绑定两个端口；不配置公网穿透。安装器不修改宿主机防火墙、不安装 Docker，也不覆盖其他应用。若本机缺 Docker，先运行诊断，把不含密码的诊断结果发回来，再按具体发行版安装。

### 已核实的上游统计连接

Songloft 官方预编译二进制和 Docker 镜像默认启用了 Tracely。固定版本源码的安装/升级统计包含主机名、版本和平台，异常上报包含错误及请求 URL；不是音乐播放必须的功能。没有发现该版本的运行时关闭开关，官方提供的关闭方式是从源码构建时不注入 Tracely 参数。

本包在 **Songloft 容器内部** 将该版本已知的统计域名 `mimusictracely.hanxi.cc` 解析为容器回环地址，并清空 HTTP/HTTPS/ALL_PROXY，阻断这一已知统计连接向外部发送。没有修改上游二进制或宿主机网络规则。这个措施针对固定版本的已知地址，不应表述为上游统计代码已移除，也不是对所有插件或未来版本的出站行为的保证。


音箱 Pro 的实际型号代码和固件尚未取得，最后要通过真实登录后的设备列表和播放测试确认。无需把 Xiaomi 账号密码填进本包安装命令。

## 4. 推荐安装步骤

### 第一步：解压到家里的 Linux 服务器

例如上传到用户自己的工作目录，解压后进入 `home-music`：

```bash
unzip home-music-starter-v0.2.0.zip
cd home-music
python3 doctor.py
python3 setup.py
```

`setup.py` 会询问服务器局域网 IP。选择音箱能访问的地址，例如 `192.168.1.100`。不要填小爱音箱自己的 IP、`127.0.0.1` 或 Docker 容器地址。

也可指定地址：

```bash
python3 setup.py --lan-ip 192.168.1.100
```

把示例 IP 替换为你的实际服务器 IP。

安装器会完成：

1. 创建随机管理员密码和独立的曲库助手密钥，写入本机 `.env`（0600）。
2. 创建持久化目录；把随包的两首试听曲及授权说明放进 `music/免费试听曲/`。
3. 拉取固定版本及 digest 的 Songloft，构建并启动曲库助手。
4. 调用 `connect_songloft.py` 安装并启用已核实版本的智能音箱插件，设置音频服务地址、语音监听、本地优先、外部搜索和“免费音乐”歌单。

重复运行会保留原密码和已有文件。插件安装或音源配置失败时，两个主服务可能已经启动；先执行诊断，再重跑连接脚本：

```bash
python3 doctor.py
python3 connect_songloft.py
```

如果已有未知版本的 MIoT 插件，连接脚本保留它并生成本地手工设置说明，不自动覆盖现有账号或设备。脚本会保留其他外部搜索源及其顺序；本包首次新建的部署只加入开放音乐来源。已有其他启用来源时，可能先匹配到其他来源的录音，请在本机核对来源优先顺序。

连接脚本现在仅在确认索引刷新时间推进后报告刷新成功；部分完成以非零退出码和明确提示返回。重用目录时会检查配置 UID/GID 的访问权限，不擅自改写已有目录权限。

### 第二步：打开主音乐软件

同一局域网的手机或电脑访问：

```text
http://你的服务器IP:58091
```

默认用户名是 `admin`。随机密码在服务器本机 `.env` 的 `SONGLOFT_ADMIN_PASSWORD` 中，可以在本机编辑器中查看，例如：

```bash
nano .env
```

`.env`、`private/` 和 `songloft-data/` 都可能含凭据，留在你自己的设备中即可，不要粘贴进聊天或发布到代码仓库。

### 第三步：绑定真实小爱音箱

在 Songloft 打开 **智能音箱 / MIoT 插件**，在账号区域发起扫码登录，使用音箱所属的小米账号完成确认。如果出现验证码或风控验证，在你自己的页面完成。

登录成功后，在设备列表勾选要接管的那台小爱音箱，启用管理。先在插件内选一首试听曲，手动点播放，确认声音真的从目标音箱发出。

自动配置已经打开语音监听、语音口令和外部搜索。若你走手工配置，参见后面的参数表。

### 第四步：做语音验收

按顺序测试：

```text
小爱同学，播放歌曲致爱丽丝。
小爱同学，暂停播放。
小爱同学，下一首。
小爱同学，播放歌曲小星星。
```

随包“致爱丽丝”是钢琴课堂录音，“小星星”是英文清唱版本。它们用于验证链路，不表示系统只有这两首歌。

若列表为空，先在 Songloft 点击“扫描”，等待完成；随后在智能音箱插件刷新音乐索引，再点播。初次配置需区分“网页能听到”与“音箱能听到”，前者不能代替后者。

## 5. 搜索、保存与中文点歌名

打开：

```text
http://你的服务器IP:58092
```

访问密钥来自 `.env` 的 `HOME_MUSIC_TOKEN`，它与 Songloft 管理密码不同。

操作：搜索歌名 → 查看录音来源和许可 → “保存到家里” → 设置中文点歌名 → 等待“已保存” → 试听或下载。

已实现的中文作品别名只有明确的少量映射：

| 说法 | 检索作品 |
|---|---|
| 致爱丽丝 / 献给爱丽丝 | Für Elise |
| 小星星 | Twinkle Twinkle Little Star |

其他歌名原样查询，也可以用英文作品名搜索后设定中文点歌名。未知商业歌曲不会被自动改成名称相似的传统歌曲。

语音点歌的示例为“小爱同学，播放歌曲晚安音乐”。“晚安音乐”需要先在曲库助手中明确绑定到你选中的那段录音。

联网查询不是完整的音乐推荐系统；如要按“放一些睡前轻音乐”自动挑选多个风格匹配作品，需要另行准备歌单或扩展分类。当前可在 Songloft 建好歌单后说“小爱同学，播放歌单睡前音乐”。

在曲库助手中手工保存的条目，现在会在保存完成后自动登记到 Songloft 及所配置的歌单，无需先语音点播。同步采用与 MIoT 相同的录音标识，重复保存、失败重试和服务重建不会主动创建重复曲目。源文件未保存完整或本机文件丢失时不会导入。若升级前的旧版本已经把残缺文件标为已保存，本版不自动覆盖旧文件；应先备份，再核对这类旧录音，不能把升级当作旧文件已经重新通过校验。请等待“已同步到主曲库和歌单”；源搜索失败、MP3 保存失败、主曲库登记失败是不同状态。不要再把同一自动下载目录交给 Songloft 扫描。

**中文点歌名改绑仍有设备侧限制：**助手会立即更新 A→B 映射，但 MIoT 既有语音记忆或本地优先搜索可能继续命中旧歌曲。本版不擅自清除你的记忆或修改其他来源顺序。改绑后需在 MIoT 界面核对/清理该口令的旧记忆，刷新索引，并实际说一次口令确认播放 B；验证前不要把网页映射成功当作音箱已经切换。也可先给 B 使用一个没有用过的新点歌名。此项仍需要家庭实机验收。

曲库页面支持“加载更多音乐”；原标题查找不受前 500 首的显示范围限制。未保存的旧音源地址失败后，语音或媒体重试会重新核对同一 Commons 页面；元数据刷新按曲目合并并限频约 30 秒，播放地址保持不变。

## 6. 手工配置与回退

需要手工配置时运行：

```bash
python3 connect_songloft.py --export-only
```

脚本在本机 `private/` 生成仅当前用户可读的设置说明。这份文件包含访问密钥，只在本机使用。

| 智能音箱配置项 | 本方案值 |
|---|---|
| 音箱访问服务器地址 `server_host` | `http://服务器局域网IP:58091` |
| 对话监听 | 开启 |
| 语音口令 | 开启 |
| 搜索策略 | 本地优先 / `local_first` |
| 外部搜索 | 开启 |
| 搜索地址 | `http://free-music:8080/api/search/topone` |
| 外部搜索 token | 完整填写 `Bearer ` 加 `.env` 的 `HOME_MUSIC_TOKEN` |
| 超时 | 30 秒 |
| 不导入外部歌曲 `external_search_no_import` | 关闭 / `false` |
| 外部歌曲导入歌单 | 免费音乐 |

这里的搜索地址是 **Songloft 容器调用曲库助手**，所以可以用 `free-music` 服务名；实际给音箱的 MP3 地址使用家庭 IP 和 58092 端口。两个地址不能混用。

MIoT 需要单独、完整的 `Bearer ...` 授权字符串；上游不会自动给自定义密钥补上这个前缀。

## 7. 免费音源的具体规则

默认使用 Wikimedia Commons 官方 MediaWiki `videoinfo` API，取得录音信息、许可和官方 MP3 衍生文件，无需音乐平台 API 密钥。

自动收录条件：

- 文件类型明确为音频；时长 20 秒至 30 分钟。
- 许可字段为可明确核实的 CC0、CC BY 或 CC BY-SA，名称和官方许可 URL 对应。
- 没有明显的额外限制、删除标记或许可字段冲突。
- 存在 Wikimedia 官方的 HTTPS MP3 转码文件。
- 明显的发音、演示、片段等标题被过滤；自动点播还要检查名称、作品编号以及上游提供的作者/标题/时长提示。

不是所有 Commons 音频都会通过这些条件。其他公有领域声明、带地域版本的许可或元数据不完整的文件，可以人工核实后导入普通曲库，不自动放宽规则。

不同国家和家庭网络对 Wikimedia 的连通性不同。首次联网搜索实测可能需要数秒；无法连接时已保存的音频仍在家里。Commons 的许可证元数据来自上传者，不是平台对版权的担保；重要的目标录音仍应看具体来源页面。

后续可接入 Jamendo 等来源，但 Jamendo 需要自己的开发者 `client_id`，且必须核对单曲的 `audiodownload_allowed` 和下载地址。当前版本没有内置这类密钥或付费服务。

## 8. 日常维护

### 查看服务

```bash
python3 doctor.py
docker compose ps
```

`doctor.py` 只输出系统、架构、Docker、目录权限和服务健康信息，不输出密码、token 或原始日志。诊断会指出缺失项；它不会替你修改系统配置。

### 停止或继续运行

```bash
docker compose stop
docker compose start
```

### 音乐容量

自动曲库默认上限 5120 MB，单个文件最多 64 MB，最多两个下载任务同时执行。容量限制是保守预留，快到上限时会提前停止接收新下载。磁盘剩余不足 128 MB 时暂停保存，不自动删除旧歌。

调整 `.env`：

```text
HOME_MUSIC_MAX_LIBRARY_MB=10240
```

然后重建容器配置：

```bash
docker compose up -d
```

### 备份

建议暂停两个服务后，备份这几项：`.env`、`music/`、`provider-data/`、`songloft-data/` 和 `private/`。备份包含小米登录信息和密钥，应保存在你控制的位置。恢复时保留原密钥、服务器 IP 和端口，已有的签名音频地址才能继续使用。

只备份 MP3 可以保住音乐，但中文别名、歌单、授权记录和设备绑定还分别保存在数据库/配置中，也需要备份。

### 更新

本包固定了已核实的 Songloft 版本和镜像 digest，没有用 `latest` 自动漂移。需要升级时先备份，再核对上游发布记录与 MIoT 插件接口。不要仅改变 `:2.13.8` 而保留旧 digest；版本和 digest 要一起更新，并重新验证连接脚本。

## 9. 常见问题

| 现象 | 优先检查 |
|---|---|
| 安装器报告没有 Docker 或 Compose | 先根据 Linux 发行版安装 Docker Engine 与 Compose v2，再重跑 |
| 镜像或插件下载失败 | 检查家里对 Docker Hub/GitHub 的连接；使用上游官方离线镜像或插件下载渠道，不随意换不明镜像 |
| 手机打不开管理页 | 服务器 IP 是否选对、Linux 防火墙、是否同一可互访局域网 |
| 网页可播放，音箱没声音 | `server_host`、58091/58092 端口可达性、设备管理开关、音箱所在网络隔离 |
| 音箱仍走原平台的播放结果 | 对话监听、语音命令是否开启；先用“播放歌曲”前缀；确认账号会话有效 |
| 搜歌为空或超时 | 免费来源可能没有该录音或网络不可达；尝试英文作品名，或导入已有 MP3 |
| 找到了歌曲，但保存失败 | 助手里的失败原因、磁盘空间、原音源网络，重试后确认“已保存” |
| 重启后语音失效 | 小米登录状态是否过期、家庭 IP 是否变化、两个容器是否正常启动 |
| 改密钥或 IP 后旧条目失效 | 旧签名地址保存了旧 token/IP；优先恢复原设置，或重新生成和导入相应条目 |
| 原有 FLAC 等文件不响 | 先用随包 MP3 验证，再按实际音箱型号配置 Songloft 转码；并非所有音箱都支持同样格式 |

## 10. 项目文件与验证

主程序是标准库 Python，容器提供 FFmpeg/FFprobe 作格式校验。可在有 Python 3.12 和 FFmpeg 的开发机运行：

```bash
python3 -m unittest discover -s tests -v
```
